# T010 实际文件夹工作区

APPROVED：用户“授权一个文件夹，工作区就在那个文件夹中，文件夹里面的内容授权后可修改”。PLAN-r3 / RULES-r6；基线a6e622c。仍为第一步修正，完成后交用户体验。

## 用户行为及边界

- 本机网页提供“选择文件夹”和绝对路径输入。Windows原生目录对话框仅在用户主动POST选择时打开，选择仅填路径，随后显式“授权此文件夹”；取消不改变现有授权。手工输入可用作备用入口。不用webkitdirectory上传冒充磁盘写权限。
- 授权只接受既有本机普通目录；拒绝相对路径、UNC、设备路径、根或父级链接/reparse。授权不创建目录/欢迎文件，不复制到demo。授权后显示完整根路径；同一会话一次一个根，切换授权废止旧根。旧demo会话键不继承新权限。
- 授权后浏览根和已有子目录，读取常见UTF-8文本/代码（txt/md/py/js/ts/jsx/tsx/json/html/css/vue/java/c/h/go等明确列表），编辑并保存到原位置；文件最大64KiB。二进制/编码/大小不支持时清楚提示且不改动。隐藏/特殊/链接文件不开放。目录每页最多100项并提示限制。
- 新建文件不覆盖。保存已有文件带读取时的版本摘要；外部变更或文件消失则拒绝保存并保留用户编辑，提示重新读取。保存以同目录临时文件+原子替换，失败清理临时文件，尽量保留原文件权限；不混淆创建与覆盖。
- 相对路径用/分隔，每段拒绝空、点段、反斜杠、绝对路径、驱动器/冒号/ADS、控制字符、保留设备名、尾点空格。逐级lstat验证普通目录，任何reparse/symlink拒绝，文件多硬链接拒绝。不允许客户端通过每次请求根字段绕过session所授权根。
- 每次列/读/创建/保存均检查服务端session授权；GET只读、所有POST保留CSRF、页面no-store、文本自动转义；撤销后读写拒绝。保存/创建POST还需匹配本次授权ID，避免切换目录后旧页面写错新目录；编辑失败保留输入。
- 仅本机127.0.0.1开发服务、Windows本机选择器；不是远程浏览器访问者的电脑选择器，不是OS沙箱，也不防本机恶意进程并发替换。不加命令执行、AI、账号、数据库模型、外部服务或依赖，不锁定桌面框架。

## 顺序与契约

T010A仅services.py及服务测试：保留旧demo帮助方法供历史验证；扩展list_files(directory='')为兼容的文件名列表，另list_directory(directory='')返回目录与可编辑文件的简单条目；validate_root()只验证不写入；read_document(path) -> (content, revision)；save_text(path, content, expected_revision) -> revision。已有read_text/create_text支持安全相对路径。不要留两套重复路径检查逻辑。

T010B接forms/views/template及选择器模块/测试：新服务端session结构root+grant_id，新授权版本键；grant、pick、revoke、create、save。路径选择器用固定PowerShell脚本/参数（不拼用户输入）、STA、无多余控制台、超时/取消处理，可mock测试；失败时路径输入仍可用。点击保存前后的编辑状态与成功/错误反馈清楚。

## 验证和停止

先写关键失败用例，再实现。必要验证：既有目录授权不写文件；子目录读取/保存真实磁盘核对；外部编辑冲突/原始内容保留；替换失败无损；遍历、父级/内部junction、symlink属性、硬链接、编码、大小、CSRF、未授权/跨会话/撤销/切换后旧grant_id；原健康测试保留。旧测试仅因边界正式改变而调整，保留其安全断言，不删除测试掩盖失败。

T010A检查服务单测和ruff后回填current/log并停，目标180秒、最长240秒；不要扩到HTTP。Codex核对后派T010B，后者检查HTTP及完整pytest/ruff/Django check。Codex用真实Chrome在专用测试夹完成授权→子目录→读写→磁盘→冲突→撤销，保留截图。原生对话框只能标实测或未实测，不因mock通过冒称已实测。

无commit/push、无额外agent；详细日志tasks/logs/T010{A,B}.log，最终简报约500汉字以TASK_RESULT标记。任何超时先检查原任务，禁止重复派发；阶段完成后不自动推进下一阶段。
