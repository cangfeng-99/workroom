# T012 P2账号与项目验收

2026-10-23，PLAN-r5 / RULES-r8。用户在P1验收后说“开始下一步”，本项实现账号、个人项目和项目工作区关联；技术检查通过，等待用户体验。本项不进入团队/任务/AI阶段。

## 体验步骤

1. 打开 http://127.0.0.1:8000/projects/ 。未登录时进入登录页；首次使用点“还没有账号？注册”，填写用户名、密码和确认密码，注册后自动登录。
2. 点“新建项目”，填写项目名称与可选说明，点“创建项目”。项目会进入本机数据库，之后可在“我的项目”中找到。
3. 在项目详情点“选择并授权文件夹”，使用已验收的页面内目录选择器选择实际文件夹，再点“授权此文件夹”。
4. 点顶部“项目”，返回刚才项目的详情，点“关联当前已授权文件夹”，再点“打开项目工作区”。该次明确关联会绑定当前授权并刷新授权版本。
5. 浏览文件、编辑保存或新建文件；改动写回原目录。退出登录后文件权限清除；重新登录仍可看到项目和目录位置，进入项目工作区后需再点“授权此文件夹”。

也可先授权独立工作区，再在新建项目页勾选关联当前文件夹。创建时的关联记录目录位置，打开项目后按页面提示授予项目上下文的文件权限。每次只使用一个当前目录授权；切换项目后旧页写入被拒绝。

## 实现与权限

- accounts使用Django原生UserCreationForm/LoginView/LogoutView，默认User模型与密码验证/哈希机制；不预置管理员、邮箱或短信服务。登录next由框架验证，退出仅POST。
- 文件页需登录；目录元数据API未登录401；原健康接口公开只读。grant含user_id/project_id，身份或项目不匹配、项目关联目录改变时不使用旧授权；成功登录/注册清除旧grant，退出清session。
- Project含owner、名称/说明、文件夹位置和时间；每个账号只访问自己的项目，详情/关联/打开/工作区query均校验owner。客户端owner/workspace_path不能修改归属或绕过当前授权。
- 模型关联只保存路径；没有当前grant不能关联，GET不授权文件。项目工作区路径必须与已关联目录一致，保存/新建/撤销重定向和文件导航保留project上下文。
- 沿用本机开发SQLite和Django页面，最终MySQL/桌面框架及远程设备授权仍未锁定。用户AI key无需提供，模型/外部AI工具连接不在本阶段。
