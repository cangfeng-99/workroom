# T010 实际文件夹授权与编辑验收

PLAN-r3 / RULES-r6，2026-10-23。用户纠正第一步的目录授权含义，本项仅覆盖这一修正；整体路线仍为草案。

## 体验入口

访问 http://127.0.0.1:8000/workspace/ 。服务仍只监听127.0.0.1:8000，沿用Run-Backend.cmd与exec session75882，未另起服务。

1. 点“选择文件夹…”并在Windows弹窗选择一个既有文件夹；也可在“文件夹完整路径”中粘贴绝对路径。
2. 点“授权此文件夹”，核对页面完整根路径。选择本身只填路径，显式授权后才开放读写；授权动作不创建目录或欢迎文件。
3. 从目录列表进入子目录，选择受支持的代码/文本文件，修改“编辑内容”后点“保存到原文件”。在原文件位置核对结果。
4. 可在当前目录新建文件，同名不会覆盖。保存已有文件时若外部软件已改动，保存被拒绝，输入仍保留；重新读取会载入磁盘版本，需先自行保留需要的编辑。
5. 更换文件夹会使旧页面的写入授权失效；点“撤销授权”后，该会话不能继续读写。

## 当前能力边界

- 工作区直接指向用户选定的既有本机文件夹及子目录；一次会话一个根，授权存在Django服务端session，旧demo授权不继承。
- 可编辑常见UTF-8代码/文本，单文件最大64KiB；每目录最多显示100个符合条件的项。隐藏、链接、硬链接、特殊项不开放；其它格式没有专用编辑器。新建不创建不存在的子目录。
- 本步提供文件读取、新建和保存，不含重命名/删除、命令执行、模型或外部AI工具连接。
- 原生Windows选择器仅有mock测试及Forms环境可用性探测，真实弹窗尚未人工验收；手动路径入口已完成真实浏览器验收。弹窗属于运行本机Django进程的电脑，未实现远程设备的目录授权。
- 这是应用级路径限制，不是OS级沙箱，未对抗本机恶意进程在检查与写入间替换路径；Windows权限保留语义未另作专项验收。失败清理和原文件保留有测试。
