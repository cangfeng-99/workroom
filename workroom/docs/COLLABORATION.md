# 协作规则如何生效

服务器项目的「项目设置 → 协作策略与交付统计」控制完整任务包、共享工作区互斥、高风险独立复核和检查证据要求。新建server项目默认启用；旧项目不会因升级自动被严格流程锁住，负责人可以明确开启。策略和任务包修改会更新上下文版本并留下审计。

## 一次任务的操作

1. 从任务树选择任务，打开「交付与验收记录」。负责人用「编辑任务包」填写工作内容、验收条件、类型、代码基准、工作区标识、允许范围、相关文件、检查命令及风险。
2. 执行者读取任务包再认领。认领保存快照、上下文版本、执行者及工具/模型信息。软件任务共享同一工作区标识时只能有一个有效执行；独立工作树需使用真实独立目录和不同标识，不能只改标识假装隔离。
3. 执行者在自己已授权的环境完成任务。规则变化时读取最新任务包并明确确认；工作区变化须先释放再领取，不能把旧租约迁移到另一个已占用工作区。
4. 提交变更清单、与快照一致的基准、检查命令/退出码/输出、证据和幂等键。超出允许范围会拒绝保存；重复提交同一内容不会重复造记录。
5. 高风险任务由另一执行者提交「独立复核意见」。同一绑定身份不能自审；建议通过不自动结束任务，有待修改意见时不能通过。
6. 负责人核对代码及证据，勾选已核对后通过，或写明原因退回。失败的检查不能用一个普通证据链接替代；交付后规则变化的旧产物需要重新确认和交付。

## 六条约定的实际边界

- 任务包、认领、工作区互斥、上下文版本、交付和验收由服务器校验，适用于网页和MCP客户端。
- 交付文件范围是对上报清单的检查；实际本机文件权限、Git基准核对和进程沙箱由用户电脑上的执行环境落实。WorkRoom不能仅凭一段自报证明程序没改其它文件。
- 检查命令只保存为要求和证据，Web服务不会执行用户填写的任意shell命令。运行检查应由批准的本机工具或CI完成，负责人可独立复跑；来源仍标为执行者上报。
- 数据库Worker空闲时由程序等待，不调用模型。外部AI自动唤醒/停止尚未提供通用执行器，连接MCP不等于能反向启动任意软件。
- 交付耗时有记录；费用为可选自报，不填显示未知，各币种单独合计。工具模型信息来自连接/执行记录，不自动将token、积分折算为钱，也不据未经验证的排名自动换人。

当前不提供依赖图调度、通用本机文件执行器或各工具内部完整思维链。需要时通过独立阶段实现和验证。
