# 单人本地版：备份与恢复

从项目首页进入「备份与恢复」。这个入口仅限本机访问；多人服务器版仍使用 SERVER.md 中的离线命令。

## 平时保存进度

点击「导出备份 ZIP」。浏览器下载一份，应用数据目录的 `backups/` 也保留一份。

包含 SQLite 中的项目、任务、对话、资料、交付、个人配置与加密凭据，以及已授权工作区内 `.workroom/` 的记忆。恢复到应用专用目录的记忆也会继续进入后续备份。

不包含代码文件夹、外部 AI 软件的登录状态、服务器 `.env`。代码请另用 Git 或自己的文件备份保存。备份含私人内容，请自己保管；校验摘要只能发现损坏，不能证明来源。

## 找回进度

1. 选择自己导出的 ZIP，点击「检查备份内容」。核对日期、项目、任务、交付和记忆数量；这时数据没有改变。
2. 勾选同意替换本机全部项目记录，再点「安排下次启动恢复」。恢复是整库替换，不是合并。尚未重启时可以取消。
3. 关闭 WorkRoom 的启动进程，再重新启动个人版。只刷新或关闭网页不会恢复。使用源码入口时，关闭启动窗口后双击根目录 `WorkRoom个人版.cmd`；临时隐藏预览由开发会话维护，不能靠关闭网页停掉后台进程。
4. 启动器先检查任务/工具认领/Worker 是否仍在执行，自动保存当前完整备份，再恢复。页面显示结果及恢复前备份位置。失败不会自动重试；处理提示后重新检查并确认。
5. 重新关联原代码工作区、重新连接外部工具。记忆位于应用数据目录 `recovered-workspaces/` 的独立新目录，不覆盖原代码文件夹。旧运行任务会停止，旧工具凭据和会话会撤销，不会自动发起模型调用。

备份需要与当前数据库结构、迁移版本一致。旧版本备份请使用生成它时的对应程序版本恢复；不要为了导入而修改备份清单。换 Windows 用户或电脑后，模型 API 密钥可能需要重新填写。

## 限制与维护

- ZIP 最大 64 MB，解压总量 256 MB，最多 2048 个文件；单个记忆文件最大 4 MB。超限会明确拒绝，不会生成漏文件的“成功备份”。
- 工作区记忆里的符号链接、junction、硬链接会被拒绝，避免绕到其它目录。备份过程中记忆变化时请稍后重试。
- 检查文件有效期 24 小时；最多保留最近 8 份临时检查文件，已安排的文件不被清理。导出的历史备份不会自动删除。
- 有项目数据且启动器发现待执行迁移时，会先生成升级前 ZIP；备份失败则不继续升级。无数据的首次启动不额外生成空备份。
- 应用启动器对同一数据目录使用进程生命周期锁，避免启动两个应用实例。手工 `manage.py runserver` 不属于这个启动流程；恢复前需要自己停止其它直连同一数据库的脚本。
