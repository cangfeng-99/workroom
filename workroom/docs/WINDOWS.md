# Windows 个人版

当前为 Windows x64 免安装预览包，随包提供 Python、SQLite、Tcl/Tk 和必要运行库。无需先安装 Python、Django 或数据库服务。

## 开始使用

1. 将 `dist/WorkRoom-0.1.0-preview.5-windows-x64.zip` 整个解压。
2. 双击文件夹内 `WorkRoom.exe`，保留旁边的 `_internal` 文件夹。
3. 等控制窗口显示已运行，浏览器会自动打开项目页。填写自己的第一个项目即可使用。
4. 首页与工作区的「使用指南」提供完整操作说明和可删除练习项目，离线内容在程序目录的 `使用指南.md`。
5. 控制窗口可重新打开工作台、进入备份、重启和退出。只关闭网页时服务仍在运行，关闭控制窗口才停止这一实例。
6. 项目内「阶段进度」展示实际叶任务完成数、待确认交付、待修改和阻碍；父节点不重复计数，展开可读原因并进入完整任务。无排期的项目不会生成假日期。
7. 拆分草稿确认前可核对前置名称；无效引用不会写入任务。模型任务失败后，先查原因再手动重试；不会自动重试或自动调用AI验收。

重复打开 exe 会定位已有工作台，不启动第二个相同数据目录的实例。模型由本人按需配置，创建项目和启动程序都不会调用模型。

默认数据位置为 `%LOCALAPPDATA%/WorkRoom`，日志在其中 `logs/desktop.log`。程序可以放在普通文件夹，数据不写进程序目录。更新前先导出备份，关闭旧版控制窗口，再打开新版 exe，保留用户数据目录。当前不同版本程序使用带版本名的目录并存，不覆盖 preview.1 产物。本包未实现自动更新或安装器卸载流程。

## 带入当前开发版项目

8020 开发预览的项目仍在源码目录 `workroom/data/db.sqlite3`。exe 默认使用独立用户数据目录，初次打开显示引导是正常情况。

在开发版导出备份 ZIP，再到 exe 的「备份与恢复」检查内容并安排恢复。控制窗口会显示「重启并恢复」，点击后开始恢复。需数据库结构和迁移版本一致。恢复前自动保留当前数据，代码文件夹不被复制或覆盖，恢复后重新关联工作区、重新连接外部工具。

不要把开发数据库直接放进 `_internal`，也不要从程序文件夹删掉运行库。完整恢复范围见 LOCAL_BACKUPS.md。

## MCP

同一个 exe 提供 `--mcp` 标准输入输出入口，连接页面会生成包含实际数据目录的参数，无需客户端额外安装 Python。MCP 使用期间保持应用运行；应用关闭时工具会明确提示先启动，握手本身不启动应用或迁移数据库。

冻结版启动/升级/恢复和 MCP 写操作使用同一数据操作锁，避免恢复时同时写入。连接配置仍仅在本人明确点击时写入，验证期间没有修改实际客户端配置。

## 从源码重建

使用 Windows x64 Python 3.12，在项目内创建专用构建虚拟环境，安装 `packaging/requirements-windows.lock`，然后执行：

```powershell
.\.tools\windows-build-env\Scripts\python.exe tools\build_windows.py
```

脚本只将 spec 明确列出的模板、静态资源、模块和运行库装入目录包，生成 ZIP 和 `.zip.sha256`。自定义 Django 钩子禁用默认的项目 SQLite 自动收集。资源和许可文件调整可用 `--package-only` 重新归档；涉及程序代码或依赖时必须完整重建。

本次官方源大文件下载中断，使用了本机固定版本发行包缓存，逐文件验证 RECORD 摘要后复制到独立构建环境；不是直接依赖开发环境的额外模块。明细见 `tasks/reports/S136-runtime-cache.json`，完整版本锁已保存。构建数据使用 `.tools/windows-build/sandbox-data`，不使用真实项目库。
